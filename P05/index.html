Masalah Nyata

Kenapa Butuh Dynamic Routing?

Bayangkan jika website Anda nantinya memiliki puluhan artikel atau catatan perkuliahan:

Pendekatan Statis (Tanpa Dynamic Route)

Harus membuat puluhan hingga ratusan rute berbeda di app.py secara manual:

@app.route('/artikel/1')
def art1():
    return render_template('art1.html')

@app.route('/artikel/2')
def art2():
    return render_template('art2.html')
# ... diulang manual untuk setiap artikel baru

Pendekatan Dinamis (Variable Rules)

Cukup 1 Rute Dinamis di Flask untuk melayani ribuan artikel sekaligus:

@app.route('/artikel/<int:id>')
def detail_artikel(id):
    # id otomatis diekstrak dari URL
    artikel = cari_artikel(id)
    return render_template(
        'detail.html',
        artikel=artikel,
        id=id
    )
Teori Dasar

Variable Rules & Converter Types

Flask menyediakan pengonversi bawaan untuk memastikan URL yang diketik pengunjung valid sesuai tipe datanya:

Converter Contoh Sintaks Keterangan
string (default) /halo/<nama> Menerima teks apapun tanpa tanda slash /
int /artikel/<int:id> Hanya menerima bilangan bulat positif (angka 0-9)
float /nilai/<float:ipk> Menerima angka desimal dengan titik
path /berkas/<path:p> Menerima teks yang mengandung tanda slash /

@app.route('/artikel/<int:id>')

    artikel = next((item for item in artikel_list if item["id"] == id), None)
    return render_template('detail.html', artikel=artikel, id=id)

# 2. Rute Dinamis Salam User (Variable Rule String: <nama>)

    return f"<h1>Halo, {nama}!</h1><p>Selamat datang di web dinamis kita.</p>"

Teori HTTP

HTTP Methods: GET vs POST

Dua metode komunikasi paling penting antara browser dan server web:

HTTP GET • "Kartu Pos Terbuka"

Digunakan untuk mengambil data. Parameter ditempel langsung di URL browser:

  • Terlihat di address bar: /search?keyword=flask
  • Dapat disimpan di Bookmark peramban
  • Ada batasan panjang URL (~2048 karakter)
  • DILARANG untuk data sensitif seperti password

HTTP POST • "Surat Amplop Tertutup"

Digunakan untuk mengirim data baru. Data dibungkus di dalam Request Body:

  • Tidak tampil di URL address bar browser
  • Tidak dapat dibookmark sembarangan
  • Ukuran data praktis tidak terbatas (cocok untuk pesan/file)
  • WAJIB untuk formulir login, kontak, atau upload

Langkah 6 • Backend

Menangani Form POST & Pola PRG di app.py

Tambahkan fungsi rute kontak() di baris paling bawah app.py untuk menerima data POST:

app.py Baris paling bawah file (sebelum if __name__) Tambahkan def kontak()
01 Konsep Dasar

Pola arsitektur standar web Post/Redirect/Get (PRG) untuk memisahkan penerimaan data form dengan rendering tampilan.

02 Fungsi Utama

Membaca masukan form via request.form.get(), memicu flash(), lalu redirect (HTTP 302) kembali ke GET.

03 Kenapa Harus Pakai Ini?
Langsung Render Tekan F5 memicu resubmission form & data terkirim ganda.
Pola PRG Dialihkan ke GET bersih. Refresh berkali-kali tetap aman.
Analogi Dunia Nyata

Pola PRG itu ibarat kasir bioskop yang menyerahkan tiket lalu menyuruhmu melangkah ke pintu teater. Setelah pembayaran diterima (POST), kasir mengarahkanmu ke lorong masuk (Redirect ke GET). Jika kamu bingung menoleh ke belakang (tekan F5), tiketmu tidak akan dipotong atau ditagih dua kali.

INFO Alur HTTP 302 Redirect

Fungsi redirect(url_for('kontak')) mengirim status HTTP 302 Found ke browser bersama header Location. Browser seketika membuat request baru GET /kontak, sehingga form input dikosongkan kembali.

app.py (Tambahkan di Paling Bawah) 
# Tambahkan di baris paling bawah app.py:
@app.route('/kontak', methods=['GET', 'POST'])
def kontak():
    if request.method == 'POST':
        nama = request.form.get('nama')
        pesan = request.form.get('pesan')
        flash(f'Terima kasih, {nama}! Pesan berhasil dikirim.', 'success')
        # Pola PRG: Selalu redirect setelah POST!
        return redirect(url_for('kontak'))
        
    return render_template('kontak.html')
Cara Cek Hasil: Simpan app.py & buka http://127.0.0.1:5000/kontak di browser. Isi nama dan pesan, klik kirim → Halaman tidak error 405 dan otomatis me-redirect ke /kontak!

# Tambahkan di baris paling bawah app.py:
@app.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'POST':
        u = request.form.get('username')
        p = request.form.get('password')
        if u == 'admin' and p == '12345':
            flash('Login berhasil! Selamat datang, Admin.', 'success')
            return redirect(url_for('home'))
        flash('Username atau password salah! Coba lagi.', 'danger')
        return redirect(url_for('login'))
    return render_template('login.html')
