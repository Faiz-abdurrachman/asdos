The Shock Moment

Mengapa HTML5 required Saja Tidak Cukup?

Banyak developer pemula mengira validasi browser sudah cukup aman. Mari kita buktikan celahnya!

Validasi Client-Side (Browser HTML5)

Memberikan atribut <input required type="email"> di file HTML.

Celah Keamanan Fatal: Siapapun bisa klik kanan → Inspect Element → hapus tulisan required dalam 3 detik, lalu submit. Data kosong pun lolos terkirim ke server!

Tujuan asli Client-Side hanyalah kenyamanan visual (UX) agar pengguna tahu ada typo tanpa menunggu loading.

Validasi Server-Side (Python Flask)

Memeriksa nilai variabel di backend Python dengan logika if-else sebelum data diterima.

Pertahanan Mutlak: Logika Python dieksekusi di server pribadimu. Pengguna sama sekali TIDAK BISA memanipulasi kode server melalui browser!

Prinsip Emas Keamanan: "Never Trust User Input." Selalu verifikasi data di sisi server.

Pondasi Backend

3 Pilar Validasi Sisi Server di Flask

Tiga teknik inti yang mengubah formulir biasa menjadi sistem penerimaan data yang aman dan profesional.

01

Sanitasi Input (.strip())

Memotong spasi kosong tak terlihat di awal & akhir string. Mencegah input tipuan " " (hanya tombol spasi) yang dianggap sah oleh validasi panjang string.

02

Error Collector (errors = [])

Mengumpulkan semua kesalahan ke dalam satu wadah list. Jika pengguna membuat 3 kesalahan sekaligus, seluruh pesan error muncul bersamaan tanpa perlu klik berulang kali.

03

Flash Kategori & Sticky Form

Jika gagal: kirim flash danger dan pertahankan nama/email lama. Jika lolos: kirim flash success dan redirect ke halaman beranda (Pola PRG).

4 Aturan Validasi Modul P06: (1) Nama ≥ 3 huruf • (2) Email berformat valid (@ dan domain .) • (3) Password ≥ 6 huruf • (4) Konfirmasi password cocok persis.
Mental Model

Alur Data: Browser ↔ Server Flask (Pola PRG)

Pahami bagaimana data registrasi member mengalir dari formulir hingga tersimpan aman.

TAHAP 1: FORM GET

Browser Meminta Form

User membuka URL /register dengan metode GET → Flask merender register.html.

TAHAP 2: KIRIM POST

Form Dikirim ke Server

User klik Daftar → Browser mengirim paket POST → Flask menangkap nilai via request.form.

TAHAP 3: EVALUASI

Uji 4 Aturan Server

Sanitasi .strip() lalu periksa nama, email, password, match → tampung eror di errors = [].

TAHAP 4: KEPUTUSAN

Flash & Redirect (PRG)

Jika salah: flash danger & sticky form. Jika valid: flash success → redirect ke beranda!

Mengapa Pola PRG (Post/Redirect/Get)? Saat data valid, kita melakukan redirect() ke rute GET agar saat user menekan F5 (refresh), tidak muncul dialog browser "Confirm Form Resubmission" yang mengganggu!

Mengapa Wajib .strip()? Karakter spasi " " (tiga spasi kosong) memiliki panjang len() == 3. Tanpa .strip(), validasi nama kosong akan tertipu dan meloloskannya! Fungsi .strip() memotong spasi tak terlihat itu.

Menerapkan 4 Aturan Validasi Sisi Server

Gunakan pola Error Collector List errors = [] untuk menampung seluruh pelanggaran.

app.py • Logika 4 Aturan Validasi 
        # 2. Wadah penampung pesan kesalahan
        errors = []

        # ATURAN 1: Nama minimal 3 karakter
        if not nama:
            errors.append('Nama lengkap wajib diisi!')
        elif len(nama) < 3:
            errors.append('Nama lengkap terlalu pendek, minimal 3 karakter!')

        # ATURAN 2: Format email valid
        if not email:
            errors.append('Alamat email wajib diisi!')
        elif '@' not in email or '.' not in email:
            errors.append('Format email tidak valid (harus mengandung @ dan domain .com/.ac.id)!')

        # ATURAN 3: Password minimal 6 karakter
        if not password:
            errors.append('Kata sandi (password) wajib diisi!')
        elif len(password) < 6:
            errors.append('Kata sandi terlalu pendek, minimal 6 karakter!')

        # ATURAN 4: Konfirmasi password cocok
        if password != confirm:
            errors.append('Konfirmasi kata sandi tidak cocok!')
Keuntungan Pola List errors: Seluruh kesalahan dikumpulkan ke dalam list. Jika pengguna membuat 3 kesalahan sekaligus, pengguna akan langsung melihat ke-3 error tersebut dalam 1 kali kirim tanpa perlu klik berulang kali!

Kode Utuh Fungsi def register() di app.py

Jika kamu terkena IndentationError di Python, cocokkan kodinganmu dengan versi utuh 25 baris ini.

app.py • def register() Utuh Tanpa Bingung 
@app.route('/register', methods=['GET', 'POST'])
def register():
    if request.method == 'POST':
        # 1. Tangkap & Sanitasi input
        nama = request.form.get('nama', '').strip()
        email = request.form.get('email', '').strip()
        password = request.form.get('password', '').strip()
        confirm = request.form.get('confirm', '').strip()

        # 2. Wadah Error Collector
        errors = []

        if not nama:
            errors.append('Nama lengkap wajib diisi!')
        elif len(nama) < 3:
            errors.append('Nama lengkap terlalu pendek, minimal 3 karakter!')

        if not email:
            errors.append('Alamat email wajib diisi!')
        elif '@' not in email or '.' not in email:
            errors.append('Format email tidak valid (harus mengandung @ dan domain .com/.ac.id)!')

        if not password:
            errors.append('Kata sandi (password) wajib diisi!')
        elif len(password) < 6:
            errors.append('Kata sandi terlalu pendek, minimal 6 karakter!')

        if password != confirm:
            errors.append('Konfirmasi kata sandi tidak cocok!')

        # 3. Keputusan Validasi
        if errors:
            for err in errors:
                flash(err, 'danger')
            return render_template('register.html')

        flash(f'Selamat datang, {nama}! Pendaftaran member kantin berhasil.', 'success')
        return redirect(url_for('home'))

    return render_template('register.html')

Wawasan Industri

Mengapa Industri Menggunakan WTForms?

Komparasi: Validasi Manual if-else vs Deklaratif Class WTForms di proyek skala besar.

Manual (Yang Kita Pelajari Hari Ini)

Menggunakan if-else murni di Python. Sangat bagus untuk memahami alur dasar validasi dan 0 dependensi library tambahan.

✓ Cocok untuk pemula • Sangat transparan

WTForms / Flask-WTF

Menulis form dalam bentuk Class OOP dengan validator bawaan (Length, Email, EqualTo) serta proteksi CSRF otomatis.

✓ Standar proyek skala menengah-besar
Contoh Deklarasi Class WTForms (Sekilas Info Industri) 
from wtforms import Form, StringField, PasswordField, validators

class RegistrationForm(Form):
    nama = StringField('Nama', [validators.Length(min=3, max=50)])
    email = StringField('Email', [validators.Email()])
    password = PasswordField('Password', [
        validators.Length(min=6),
        validators.EqualTo('confirm', message='Password tidak cocok')
    ])
    confirm = PasswordField('Konfirmasi Password')
Keamanan Web

Mengenal Bahaya CSRF (Cross-Site Request Forgery)

Bagaimana penyerang bisa memanipulasi pengiriman formulir dan bagaimana cara mencegahnya.

Skenario Serangan CSRF

Penyerang memancing pengguna yang sedang login di website kampus/bank untuk mengklik link palsu di website berbahaya. Browser otomatis mengirimkan cookie sesi pengguna, sehingga server mengira transaksi itu sah dari pengguna!

Solusi: CSRF Token

Server menyelipkan token acak sekali pakai di tag form: <input type="hidden" name="csrf_token" value="...">. Saat form di-submit, server mencocokkan token. Website luar tidak tahu token ini, sehingga serangan gagal total!

Pada Flask-WTF, proteksi CSRF diaktifkan cukup dengan menuliskan tag {{ form.csrf_token }} di dalam form HTML.
Freshmen Shield

Panduan Solusi 5 Eror Paling Populer Pemula

Mengalami kendala saat live coding? Cek 5 masalah klasik ini sebelum memanggil asdos!

1. RuntimeError: The session is unavailable because no secret_key was set.
Penyebab: Lupa menentukan kunci rahasia untuk flash messages di backend Flask.
Solusi: Tambahkan app.secret_key = 'kunci-rahasia-kantin-p06' setelah inisialisasi Flask.
2. 405 Method Not Allowed
Penyebab: Form dikirim via POST, tetapi rute @app.route('/register') belum menyertakan methods=['GET', 'POST'].
Solusi: Tambahkan parameter methods=['GET', 'POST'] pada decorator rute.
3. Nilai input selalu None atau kosong di request.form.get()
Penyebab: Lupa menambahkan atribut name="..." di tag <input> HTML register.html.
Solusi: Pastikan name="nama", name="email", name="password", dan name="confirm" terisi cocok.
4. NameError: name 'flash' is not defined
Penyebab: Belum mengimpor fungsi flash atau redirect dari modul flask di baris paling atas app.py.
Solusi: from flask import Flask, render_template, request, flash, redirect, url_for
5. Pesan flash tidak muncul sama sekali di browser
Penyebab: Lupa memasang blok container get_flashed_messages() di dalam template induk base.html.
Solusi: Pastikan ada {% with messages = get_flashed_messages(with_categories=true) %} di base.html
