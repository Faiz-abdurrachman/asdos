SEKARANG • P-06

Form Handling & Validasi Sisi Server

Di P-05 kita menerima input apa adanya. Di P-06, kita memasang "Satpam Digital": data diperiksa secara ketat di server Flask sebelum diterima. Menjamin data bersih, tidak kosong, dan sesuai format keamanan!

Reality Check Keamanan

Mengapa HTML5 required Saja TIDAK CUKUP?

Validasi Client-Side (Browser)

Memberikan atribut <input required minlength="6"> di HTML.

Kelemahan Fatal: Siapapun bisa klik kanan → Inspect Element → hapus tulisan required, lalu klik submit. Data kosong pun lolos terkirim!

Tujuan Client-Side: User Experience (UX) agar pengguna tidak perlu menunggu loading untuk typo kecil.

Validasi Server-Side (Python Flask)

Memeriksa data di backend Python dengan logika if-else sebelum diproses.

Pertahanan Mutlak: Kode Python dieksekusi di server kita sendiri. Pengguna TIDAK BISA memodifikasi atau menembusnya melalui browser!

Prinsip Emas: "Never Trust User Input." Validasi server adalah garda terdepan keamanan web.

Konsep Utama

3 Pilar Validasi Sisi Server di Flask

01

Sanitasi Input (.strip())

Memotong spasi kosong di awal dan akhir string. Mencegah input tipuan seperti " " (hanya spasi bar) yang dianggap lolos validasi panjang.

02

Error Collector (errors = [])

Menampung semua pelanggaran aturan ke dalam satu list. Jika pengguna membuat 3 kesalahan, semua pesan error muncul sekaligus, bukan satu per satu.

03

Flash & Sticky Form

Jika gagal: kirim flash danger dan pertahankan isi input lama. Jika sukses: kirim flash success dan redirect ke tujuan.

4 Aturan Validasi Modul P06: (1) Nama ≥ 3 karakter • (2) Email ada @ dan . • (3) Password ≥ 6 karakter • (4) Konfirmasi password cocok.

Peringatan: Jika parameter methods=['GET', 'POST'] lupa ditulis, default Flask hanya mengizinkan GET, yang akan memicu eror 405 Method Not Allowed saat form di-submit!

Langkah 3A: Edit File • app.py

Menangkap Input & Sanitasi dengan .strip()

Perbarui fungsi register() untuk menangkap request POST.

app.py • def register() 
@app.route('/register', methods=['GET', 'POST'])
def register():
    if request.method == 'POST':
        # 1. Menangkap input dan memotong spasi kosong di awal/akhir string
        nama = request.form.get('nama', '').strip()
        email = request.form.get('email', '').strip()
        password = request.form.get('password', '').strip()
        confirm = request.form.get('confirm', '').strip()
        
        # Lanjut ke langkah 3B (validasi)
        
    return render_template('register.html')
Mengapa wajib .strip()? String " " (tiga spasi) memiliki len() == 3. Tanpa .strip(), validasi kosong akan tertipu dan menganggap nama tersebut sah!
Langkah 3B: Tempel di Dalam • if request.method == 'POST':

Menerapkan 4 Aturan Validasi Sisi Server

Gunakan pola Error Collector List errors = [].

app.py • Logika 4 Aturan Validasi 
        # 2. Wadah penampung pesan kesalahan
        errors = []

        # ATURAN 1: Nama minimal 3 karakter
        if not nama:
            errors.append('Nama lengkap wajib diisi!')
        elif len(nama) < 3:
            errors.append('Nama lengkap terlalu pendek, minimal 3 karakter!')

        # ATURAN 2: Format email valid
        if not email:
            errors.append('Alamat email wajib diisi!')
        elif '@' not in email or '.' not in email:
            errors.append('Format email tidak valid (harus mengandung @ dan domain .com/.ac.id)!')

        # ATURAN 3: Password minimal 6 karakter
        if not password:
            errors.append('Kata sandi (password) wajib diisi!')
        elif len(password) < 6:
            errors.append('Kata sandi terlalu pendek, minimal 6 karakter!')

        # ATURAN 4: Konfirmasi password cocok
        if password != confirm:
            errors.append('Konfirmasi kata sandi tidak cocok!')
Langkah 4: Tempel di Bawah Pengecekan Aturan • app.py

Flash Messages (Danger vs Success) & PRG

Memberikan umpan balik visual yang jelas ke pengguna.

app.py • Pengiriman Flash Messages 
        # 3. Evaluasi Hasil Validasi
        if errors:
            # Jika ada error: kirim flash danger lalu render ulang form
            for err in errors:
                flash(err, 'danger')
            return render_template('register.html')

        # Jika LOLOS SEMUA validasi: kirim flash success & redirect ke beranda (PRG)
        flash(f'Selamat datang, {nama}! Pendaftaran member kantin berhasil.', 'success')
        return redirect(url_for('home'))
Mengapa Pola PRG (Post/Redirect/Get)? Saat sukses, kita melakukan redirect() ke rute GET agar saat pengguna menekan tombol refresh (F5), tidak muncul dialog browser "Confirm Form Resubmission" yang mengganggu!

Wawasan Industri (Opsional)

Mengapa Industri Menggunakan WTForms?

Komparasi: Validasi Manual vs Deklaratif Class WTForms

Manual (Yang Kita Pelajari Hari Ini)

Menggunakan if-else murni di Python. Sangat bagus untuk memahami alur dasar validasi dan tidak memerlukan instalasi library tambahan.

✓ Cocok untuk pemula • 0 Dependencies

WTForms / Flask-WTF

Menulis form dalam bentuk Class OOP dengan validator bawaan (Length, Email, EqualTo) dan otomatis menyertakan proteksi CSRF.

✓ Standar proyek skala menengah-besar
Contoh Deklarasi WTForms (Sekilas Info) 
from wtforms import Form, StringField, PasswordField, validators

class RegistrationForm(Form):
    nama = StringField('Nama', [validators.Length(min=3, max=50)])
    email = StringField('Email', [validators.Email()])
    password = PasswordField('Password', [
        validators.Length(min=6),
        validators.EqualTo('confirm', message='Password tidak cocok')
    ])
    confirm = PasswordField('Konfirmasi Password')
Konsep Keamanan Web

Mengenal Bahaya CSRF (Cross-Site Request Forgery)

Skenario Serangan CSRF

Penyerang memancing pengguna yang sedang login di website bank/kampus untuk mengklik link palsu di website berbahaya. Browser otomatis mengirimkan cookie sesi pengguna, sehingga server mengira transaksi itu sah dari pengguna!

Solusi: CSRF Token

Server menyelipkan token acak sekali pakai di tag form: <input type="hidden" name="csrf_token" value="...">. Saat form di-submit, server mencocokkan token. Website jahat dari luar tidak tahu token ini, sehingga serangan gagal!

Pada Flask-WTF, proteksi CSRF diaktifkan cukup dengan menulis {{ form.csrf_token }} di dalam form HTML.
Freshmen Shield

Panduan Solusi 5 Eror Paling Populer Pemula

1. RuntimeError: The session is unavailable because no secret_key was set.
Penyebab: Lupa menentukan kunci rahasia untuk flash messages di backend Flask.
Solusi: Tambahkan app.secret_key = 'kunci-rahasia-kantin-p06' setelah app = Flask(__name__)
2. 405 Method Not Allowed
Penyebab: Form dikirim via POST, tetapi rute @app.route('/register') belum menyertakan methods=['GET', 'POST'].
Solusi: Pastikan parameter methods=['GET', 'POST'] terpasang di decorator rute.
3. Nilai input selalu None atau kosong di request.form.get()
Penyebab: Lupa menambahkan atribut name="..." di tag <input> HTML register.html.
Solusi: Pastikan ada name="nama", name="email", name="password", dan name="confirm".
4. NameError: name 'flash' is not defined
Penyebab: Belum mengimpor fungsi flash atau redirect dari modul flask di baris paling atas app.py.
Solusi: from flask import Flask, render_template, request, flash, redirect, url_for
