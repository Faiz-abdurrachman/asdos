Konsep Inti

Pergeseran Paradigma: SSR vs Headless REST API

Mengapa web modern memisahkan backend murni penyedia data dari frontend penampil UI?

P01 — P06: SERVER-SIDE RENDERING (SSR)

Monolitik Flask + Jinja2 HTML

  • Browser meminta URL ➔ Server Flask merender data ke template HTML.
  • Mengembalikan dokumen HTML utuh seberat puluhan kilobyte.
  • Kelemahan: Setiap klik tombol memicu Full Page Reload (kedipan putih layar). Data tidak bisa dipakai langsung oleh aplikasi Android/iOS.
P07: CLIENT-SERVER DECOUPLING (REST API)

Headless Flask + JSON + Vanilla JS

  • Backend murni mengembalikan data mentah berformat JSON.
  • Frontend (Browser, Mobile App, Smartwatch) meminta data via fetch() di balik layar.
  • Keunggulan: Halaman tidak pernah reload! DOM diperbarui secara instan, hemat kuota bandwidth, dan 1 backend melayani multi-platform.

3 Aturan Emas Penulisan JSON:

1

Wajib Tanda Petik Ganda ("..."): Kunci (keys) dan nilai string harus diapit double quotes. Petik tunggal ('...') akan menghasilkan syntax error.

2

Tipe Data Kaya: Mendukung string, number (tanpa petik), boolean (true/false lowercase), array ([...]), dan nested object ({...}).

3

Tanpa Trailing Comma: Jangan beri koma setelah elemen terakhir dalam object atau array.

Semantik HTTP

HTTP Verbs & Kode Status Semantik

Bahasa isyarat standar antara Client dan Server dalam arsitektur RESTful.

4 Kata Kerja HTTP (CRUD Mapping)

GET Membaca / mengambil data (Read)
POST Membuat / menambah data baru (Create)
PUT Memperbarui data yang ada (Update)
DELETE Menghapus data tertentu (Delete)

5 Kode Status HTTP Paling Penting

200 OK Permintaan berhasil diproses.
201 Created Resource data baru berhasil dibuat.
400 Bad Request Data input salah format / tidak lengkap.
404 Not Found Data ID yang dicari tidak ada di server.
500 Server Error Server mengalami crash/bug di kodingan.

Langkah 0

Inisialisasi Server & Data In-Memory

Import jsonify & request, serta siapkan database sementara berbentuk List of Dictionaries.

app.py (Langkah 0) 
from flask import Flask, render_template, request, jsonify
import requests

app = Flask(__name__)

# Database sementara di memori RAM
menu_kantin = [
    {"id": 1, "nama": "Nasi Goreng Spesial", "harga": 15000, "kategori": "Makanan", "stok": 20},
    {"id": 2, "nama": "Mie Ayam Bakso", "harga": 13000, "kategori": "Makanan", "stok": 15},
    {"id": 3, "nama": "Es Teh Manis Jumbo", "harga": 5000, "kategori": "Minuman", "stok": 50}
]

def cari_menu_by_id(item_id):
    """Mencari dictionary menu berdasarkan ID"""
    for item in menu_kantin:
        if item["id"] == item_id:
            return item
    return None

Mengapa Perlu Helper `cari_menu_by_id`?

Di tahap pemula, kita belum memakai SQL database. Fungsi bantuan ini memudahkan kita mencari elemen di dalam list Python tanpa harus mengulang-ulang perulangan for di setiap rute GET detail, PUT, maupun DELETE.

Prinsip DRY (Don't Repeat Yourself): Satu fungsi pencarian untuk 3 endpoint yang berbeda.
Endpoint GET

Membaca Data: GET Semua Menu & Detail ID

Mengubah list Python menjadi format JSON menggunakan fungsi jsonify().

app.py (GET Routes) 
# 1. Mengambil seluruh menu
@app.route('/api/menu', methods=['GET'])
def get_all_menu():
    return jsonify({
        "status": "success",
        "total": len(menu_kantin),
        "data": menu_kantin
    }), 200

# 2. Mengambil detail satu menu
@app.route('/api/menu/', methods=['GET'])
def get_menu_by_id(item_id):
    item = cari_menu_by_id(item_id)
    if not item:
        return jsonify({
            "status": "error",
            "pesan": f"Menu ID {item_id} tidak ditemukan!"
        }), 404

    return jsonify({"status": "success", "data": item}), 200

Poin Kritis untuk Mahasiswa:

  • Fungsi jsonify(): Mengubah tipe data Python (dict/list) ke format JSON string dan otomatis menyetel header HTTP Content-Type: application/json.
  • Tuple Status Code: return jsonify(...), 200 atau 404 secara eksplisit memberi tahu status ke client.
  • Variable Rule: <int:item_id> menjamin bahwa Flask hanya memproses parameter yang bertipe angka integer.
Endpoint POST

Menambah Data: POST Menu Baru & Validasi

Menangkap JSON body dengan request.get_json() dan mengembalikan status 201 Created.

app.py (POST Route) 
@app.route('/api/menu', methods=['POST'])
def tambah_menu():
    data = request.get_json()
    if not data:
        return jsonify({"status": "error", "pesan": "Body JSON wajib disertakan!"}), 400

    nama = data.get('nama', '').strip()
    harga = data.get('harga')
    kategori = data.get('kategori', 'Makanan').strip()
    stok = data.get('stok', 0)

    # Validasi input sederhana
    if not nama or not isinstance(harga, (int, float)) or harga <= 0:
        return jsonify({"status": "error", "pesan": "Nama wajib diisi dan harga harus angka > 0!"}), 400

    # Auto-generate ID baru
    new_id = max([i['id'] for i in menu_kantin], default=0) + 1
    item_baru = {"id": new_id, "nama": nama, "harga": int(harga), "kategori": kategori, "stok": int(stok)}
    menu_kantin.append(item_baru)

    return jsonify({"status": "success", "pesan": "Menu berhasil ditambahkan!", "data": item_baru}), 201

Mengapa Status 201 Bukan 200?

Menurut standar arsitektur REST, pembuatan resource baru harus mengembalikan kode 201 Created. Ini membedakan antara sekadar membaca data (200) dengan berhasil melahirkan record data baru di sistem.

Freshmen Trap: Jika di Postman lupa memilih format raw -> JSON, maka request.get_json() akan mengembalikan None dan memicu error!

Melengkapi CRUD: Endpoint PUT & DELETE

Memperbarui atribut menu yang sudah ada dan menghapusnya dari daftar.

app.py (PUT & DELETE) 
# 3. Update Menu (PUT)
@app.route('/api/menu/', methods=['PUT'])
def update_menu(item_id):
    item = cari_menu_by_id(item_id)
    if not item:
        return jsonify({"status": "error", "pesan": "Menu tidak ditemukan!"}), 404

    data = request.get_json() or {}
    if 'nama' in data: item['nama'] = data['nama']
    if 'harga' in data and data['harga'] > 0: item['harga'] = int(data['harga'])
    if 'stok' in data: item['stok'] = int(data['stok'])

    return jsonify({"status": "success", "pesan": "Menu diperbarui!", "data": item}), 200

# 4. Hapus Menu (DELETE)
@app.route('/api/menu/', methods=['DELETE'])
def hapus_menu(item_id):
    item = cari_menu_by_id(item_id)
    if not item:
        return jsonify({"status": "error", "pesan": "Menu tidak ditemukan!"}), 404

    menu_kantin.remove(item)
    return jsonify({"status": "success", "pesan": f"Menu '{item['nama']}' dihapus!"}), 200

Postman

Mengenal Postman: Klien Penguji REST API

Mengapa kita tidak bisa menguji POST, PUT, dan DELETE hanya menggunakan browser biasa?

Batasan Address Bar Browser

Saat kamu mengetik http://127.0.0.1:5000/api/menu di address bar Chrome atau Edge, browser hanya bisa mengirim request HTTP bertipe GET.

Browser tidak menyediakan antarmuka untuk menyisipkan header kustom atau request body JSON untuk menguji POST/PUT/DELETE. Di sinilah Postman hadir sebagai simulator klien serbaguna.

4 Bagian Utama Antarmuka Postman:

1. Method Selector & URL: Dropdown GET, POST, PUT, DELETE dan kolom URL target.
2. Tab Headers: Menentukan metadata seperti Content-Type: application/json.
3. Tab Body: Tempat mengetik payload JSON mentah (Pilih opsi raw -> JSON).
4. Response Viewer: Menampilkan status code (200, 201, 404), waktu respon, dan isi JSON balasan.

Server-to-Server

Konsumsi API Eksternal via Library `requests`

Menjadikan server Flask kita sebagai client yang memanggil server pihak ketiga di internet.

Terminal Instalasi & Contoh Sederhana 
# 1. Install library requests
pip install requests

# 2. Contoh kode Python menghubungi API luar
import requests

url = "https://api.open-meteo.com/v1/forecast?latitude=-6.2088&longitude=106.8456¤t_weather=true"

response = requests.get(url, timeout=5)
if response.status_code == 200:
    data = response.json()
    suhu = data['current_weather']['temperature']
    print(f"Suhu kampus saat ini: {suhu}°C")

Mengapa Perlu Library `requests`?

Python memiliki modul bawaan urllib, namun kodenya sangat rumit dan kuno. Library requests adalah standar emas industri yang membuat komunikasi HTTP semudah memanggil requests.get() dan response.json().

Keunggulan Open-Meteo: Tidak butuh pendaftaran akun, 100% bebas biaya, dan tanpa API Key yang memakan waktu aktivasi!
Smart Feature

Fitur Rekomendasi Menu Berdasarkan Cuaca

Endpoint /api/cuaca-kampus memetakan suhu cuaca real-time ke rekomendasi hidangan kantin.

app.py (/api/cuaca-kampus) 
@app.route('/api/cuaca-kampus', methods=['GET'])
def get_cuaca_kampus():
    url = "https://api.open-meteo.com/v1/forecast?latitude=-6.2088&longitude=106.8456¤t_weather=true"
    try:
        res = requests.get(url, timeout=5)
        res.raise_for_status()
        current = res.json().get('current_weather', {})
        suhu = current.get('temperature', 28.0)

        # Logika rekomendasi menu
        if suhu >= 30.0:
            saran = "Cuaca terik! Rekomendasi: Es Teh Manis Jumbo!"
        elif suhu <= 25.0:
            saran = "Cuaca sejuk/hujan! Rekomendasi: Mie Ayam Bakso Panas!"
        else:
            saran = "Cuaca nyaman! Semua menu siap dinikmati."

        return jsonify({"status": "success", "suhu_celcius": suhu, "rekomendasi_menu": saran}), 200
    except requests.RequestException:
        # Fallback ramah jika offline
        return jsonify({"status": "fallback", "suhu_celcius": 28.5, "rekomendasi_menu": "Es Teh Manis Jumbo selalu aman!"}), 200

Kecerdasan Kontekstual Aplikasi

Inilah bukti nyata kekuatan API: Aplikasi kantinmu bukan sekadar tabel data statis, melainkan aplikasi pintar yang terhubung dengan dunia luar dan memberikan rekomendasi otomatis kepada mahasiswa!

Fallback Mode: Blok try-except menjamin aplikasi tidak crash meskipun laptop mahasiswa sedang terputus dari internet di dalam lab.
Client-Side AJAX

Frontend Asynchronous: Mengenal JavaScript `fetch()`

Mengirim dan menerima data di balik layar tanpa perlu memicu refresh halaman web.

script.js (async / await) 
// 1. Memanggil GET dengan fetch
async function muatMenu() {
    const res = await fetch('/api/menu');
    const json = await res.json();
    console.log("Data menu:", json.data);
}

// 2. Mengirim POST dengan fetch
async function kirimMenu(menuBaru) {
    const res = await fetch('/api/menu', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json' // Wajib!
        },
        body: JSON.stringify(menuBaru)
    });
    const hasil = await res.json();
    alert(hasil.pesan);
}

Anatomi Penting Fetch API:

• async/await: Menunggu server merespon tanpa membekukan antarmuka pengguna (UI tetap responsif).
• headers: {'Content-Type': 'application/json'}: Memberi sinyal kepada Flask bahwa data yang dikirim adalah format JSON.
• JSON.stringify(): Mengubah objek JavaScript menjadi string JSON baku sebelum dikirim ke kabel jaringan.

Freshmen Shield

Antisipasi 4 Eror Populer & Solusi Kilat

Katalog eror yang paling sering dialami mahasiswa semester 3 saat belajar API.

EROR 1: request.get_json() return None

Penyebab: Lupa menyertakan header Content-Type: application/json di Postman atau fetch.
Solusi: Di Postman pilih raw → JSON. Di fetch tambahkan properti headers.

EROR 2: ModuleNotFoundError: 'requests'

Penyebab: Menjalankan program di luar virtual environment aktif.
Solusi: Pastikan prompt terminal diawali (venv), lalu ketik pip install requests.

EROR 3: 405 Method Not Allowed

Penyebab: Rute Flask hanya mengizinkan GET, tetapi ditembak dengan POST.
Solusi: Cek decorator rute, pastikan mencantumkan methods=['POST'] atau method yang sesuai.

EROR 4: JSONDecodeError di Browser / Terminal

Penyebab: Menuliskan tanda petik satu (') atau ada koma berlebih di akhir object JSON.
Solusi: JSON standar hanya mengenali petik dua (") dan tidak boleh ada trailing comma.
